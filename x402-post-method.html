What was measured

For each seller in our census we took the routes that answer GET with a real 402 — the ones a seller advertises as paid — and sent the same route a POST with an empty JSON body and no payment. A working seller answers 402 plus a challenge either way. This page is the result of 137 such requests across 78 hosts, first measured 2026-10-30 and re-run 2026-11-14.

Reproduce it

No client library, no key, no payment. Take any route a seller charges for and change the verb:

curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  -H 'Content-Type: application/json' -d '{}' \
  https://<seller>/<their-paid-route>

402 means they sell to agents. 405 means they sell to curl -X GET. 404 means the route they published does not exist for the verb an agent tool chose.

Our own server had this defect

Before pointing at anyone else we ran the same check against our own paid routes. Every GET route charged correctly and every POST to the same path returned 405 — a free bypass for any client that picked the other verb. Fixed 2026-10-30: POST twins for every paid GET route, so the unpaid POST now gets the same 402 and the same price. Re-verified by a daily selftest, and you can check it yourself right now:

for m in GET POST; do curl -s -o /dev/null -w "$m %{http_code}\n" -X $m \
  -H 'Content-Type: application/json' -d '{}' https://03s9tr085tfe5agke0tpqng34o.ingress.quanglong.org/x402/feed; done
